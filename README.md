# 🔐 Цифровий підпис зображень із приховуванням (RSA + LSB)

## 📌 Опис проєкту

Цей Python-проєкт реалізує **цифровий підпис зображення** за допомогою алгоритму RSA (4096 біт) 
та **приховує підпис у пікселях** зображення методом LSB (Least Significant Bit).

Підписане зображення:
- підтримується лише у форматі **PNG** (через його безвтратну природу),
- виглядає візуально ідентичним оригіналу,
- відкривається звичайними переглядачами,
- містить **невидимий цифровий підпис**, що гарантує автентичність.

📁 Структура проєкту:

```
├── generate_keys.py         # Генерація RSA ключів (4096 біт)
├── sign_image.py            # Підписування PNG-зображень та вбудовування підпису
├── verify_sign.py           # Витягування та перевірка цифрового підпису
├── requirements.txt         # Залежності проєкту (Pillow, cryptography)
├── LICENSE                  # Ліцензія проєкту
├── README.md                # Документація (також є в docstring у коді)

├── keys/                    # Папка для збереження RSA ключів
│   ├── private_key.pem      # Приватний ключ (використовується лише для підпису)
│   └── public_key.pem       # Публічний ключ (використовується для перевірки)

├── images/                  # Робоча директорія зображень
│   ├── original_images/     # Оригінальні PNG-зображення, які підписуються
│   └── signed_images/       # Підписані PNG-зображення з прихованим підписом
```

📌 Усі зображення повинні бути у форматі **.png**, оскільки JPEG та інші з втратою даних 
не підходять для точного LSB-стеганографічного вбудовування і також я обрала **.png** формат.

## 🧩 Основні компоненти

1. **generate_keys.py**
    - Генерує пару RSA-ключів (4096 біт).
    - Зберігає приватний і публічний ключі у папці `keys/`.

2. **sign_image.py**
    - Зчитує зображення у `images/original_images/`.
    - Створює підпис (SHA-256 + RSA).
    - Вбудовує його в пікселі PNG-зображення (у LSB червоного каналу).
    - Зберігає результат у `images/signed_images/`.

3. **verify_sign.py**
    - Витягує вбудований підпис із PNG-файлу.
    - Перевіряє автентичність за публічним ключем.

## 🛠 Алгоритм

У проєкті використано поєднання двох підходів:
1. Криптографічний цифровий підпис із використанням **RSA (4096 біт)**.
2. Приховане вбудовування підпису методом **LSB (Least Significant Bit)** у зображення у форматі **PNG**.

### 🔐 RSA (4096 біт)
RSA — це один із найнадійніших та найпоширеніших алгоритмів асиметричної криптографії.  
У даному проєкті:
- **Приватний ключ** використовується для створення підпису,
- **Публічний ключ** — для перевірки автентичності підпису.

Цифровий підпис створюється шляхом хешування вмісту зображення (SHA-256) і шифрування хешу приватним ключем.  
Це гарантує:
- **цілісність** (неможливо змінити вміст зображення без втрати валідності підпису),
- **автентичність** (перевірка джерела через публічний ключ),
- **невід’ємність** (відправник не може заперечити факт підпису).

Чому саме 4096 біт?
- Це підвищує рівень безпеки (стандарт для довготривалого зберігання та високих вимог до захисту),
- Стійкість до атак на майбутнє (наприклад, якщо ключ зберігатиметься багато років).

---

### 📥 LSB (Least Significant Bit) — стеганографія
Метод LSB дозволяє вбудовувати інформацію у зображення, змінюючи **найменш значущі біти** пікселів.  
У нашому випадку:
- Підпис вставляється в **молодший біт червоного каналу** кожного пікселя.
- Це зміна на рівні, непомітному для людського ока — зображення виглядає незмінено.

Переваги:
- Висока **непомітність** (підпис "схований"),
- Простота реалізації та зчитування,
- Не потребує додаткових метаданих у файлі.

Недолік:
- Така інформація зберігається тільки у **безвтратних форматах** (тобто PNG).

---

### 🖼 Чому лише PNG

Формат **PNG (Portable Network Graphics)** обрано з таких причин:
- Він **не стискає з втратами** (на відміну від JPEG), тобто значення кожного пікселя зберігається точно.
- Підтримує **24-бітну глибину кольору** і **альфа-канал**, що дозволяє гнучко працювати з кольоровою інформацією.
- Збереження EXIF-даних (метаданих) після редагування.

Це критично важливо для LSB, бо будь-яке втратне стиснення (як у JPEG) обнуляє або спотворює молодші біти, в яких і зберігається підпис.

---

🔐 Таким чином, проєкт поєднує:
- **криптографічну надійність (RSA)** з
- **стеганографічною невидимістю (LSB у PNG)**.

Це дозволяє створити зображення, яке виглядає як звичайне, але містить доказ його справжності.

## 🚀 Як користуватись

1. Згенерувати ключі (одноразово):

```bash
python generate_keys.py
```

2.	Підписати зображення:
- Помістіть ваші зображення у папку:
```bash
images/original_images/
```

- Запустіть:
```bash
python sign_image.py
```

- Підписані зображення з’являться у:
```bash
images/signed_images/
```

3.	Перевірити підпис:
```bash
python verify_sign.py
```
У терміналі буде виведено повідомлення, чи є підпис дійсним.
